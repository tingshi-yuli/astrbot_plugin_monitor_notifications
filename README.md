# 哈工深官网通知提醒

自动登录[哈工深办公信息网](http://info.hitsz.edu.cn/list.jsp?urltype=tree.TreeTempUrl&wbtreeid=1053)，检测新通知并推送到指定 QQ 私聊。新通知包含标题、日期、原文链接和可选 AI 摘要；引用这条通知，或紧接着直接回复“详细”等，可获取保存的正文和内嵌图片。

默认每 1 小时检查前 3 页，间隔至少 15 分钟。首次成功抓取只建立基线，之后按通知 ID 判断新增。通知日期较旧但 ID 首次出现，也会推送。

## 配置

在 AstrBot 安装插件和 `requirements.txt` 中的依赖，填写配置后重载：

| 配置项 | 填写内容 |
| --- | --- |
| `username` | 学校统一身份认证账号（学号/工号） |
| `password` | 学校统一身份认证密码，本地保存 |
| `target_umo` | QQ OneBot 私聊 UMO，例如 `QQ:FriendMessage:1351005269` |
| `poll_interval_seconds` | 默认 3600 秒，最小 900 秒；已有配置保持原值 |
| `enable_ai_summary` | 是否附带 AI 摘要，默认开启 |
| `summary_provider_id` | 可选 AstrBot 模型提供商 ID；留空使用目标会话当前的模型 |
| `detail_triggers` | 默认 `详细`、`全文`、`原文`、`展开`、`打包`，可增加短语 |

私聊发送 AstrBot 自带的 `/sid` 获取完整 UMO。当前版本的引用与打包功能支持 QQ OneBot 私聊，发送回执来自 `send_private_msg`，合并转发使用 `send_private_forward_msg`。

**目标会话所用配置中的插件白名单需包含本插件，或允许全部插件。**后台检测可以运行，但如果会话未启用本插件，引用回复不会进入插件处理器。确认 OneBot 平台 ID 与 UMO 第一段一致。使用 AstrBot 插件启停控制运行，没有额外的管理命令。

## 摘要与完整正文

检测到新通知后，插件复用学校会话抓取详情，并保存正文段落、文本表格、内嵌图片和附件名称/链接。摘要仅使用抓取的正文文字；图片和附件不参与总结，有这些内容时会标明摘要范围。

开启摘要会将通知标题、日期和正文文字发送给所选模型服务；账号、密码、Cookie 和聊天历史不会放入提示词，也不启用工具。摘要限制等待 25 秒；未配置模型、超时、异常、图片为主或正文超过 24000 字符时会明确提示摘要不可用，基础通知继续发送。关闭摘要仍保存正文，支持后续索取全文。

例如，检测到道路施工通知，QQ 消息如下（摘要为示例）：

```text
【哈工深新通知】
关于10月12日至10月25日大学城学苑大道与丽水路交汇路口北侧通道口施工封闭的通知
日期：2026-10-10
https://info.hitsz.edu.cn/content.jsp?urltype=news.NewsContentUrl&wbtreeid=1023&wbnewsid=9631

AI 摘要：
10月12日至25日，学苑大道与丽水路交汇路口北侧通道口因施工封闭。非机动车及行人需提前规划路线、绕道通行，各单位应提醒师生员工注意安全。
（摘要仅依据正文文字，未解读图片及附件。）
```

推送不附带引用回复的操作引导。用户引用该消息回复“详细”，或“请把这条通知的完整内容发我”，插件会拦截这一请求并发送合并转发包，包括原通知元信息、未删节正文、内嵌图片及附件清单。文本按 1500 字符分段，每包最多 20 个节点；表格按行转为文本，标注合并单元格跨度，不保留网页排版。

正文请求只在配置的目标私聊生效，普通聊天不会被接管。通过 QQ 消息 ID 对应到本地通知快照，重启仍可使用。旧版通知没有映射时，会向 QQ 查询原消息，确认是当前机器人发出的通知且通知 ID 在本地已见记录内，才恢复映射；QQ 无法查询的旧消息不能保证恢复。

v0.3.1 新增直接回复：收到通知后不使用 QQ 引用，直接发送“详细”等触发词也可以取正文，条件是**通知与这条请求之间没有其他消息**。按消息相邻判断，不设置分钟数限制；显式引用始终优先，引用未匹配时不会改选其他通知。

| 消息顺序 | 处理结果 |
| --- | --- |
| 通知 A → 详细 | 发送 A 的正文 |
| 通知 A → 通知 B → 详细 | 发送 B 的正文 |
| 通知 A → 用户其他消息 / 机器人普通回复 / 其他插件推送 → 详细 | 不自动获取通知正文 |
| 中间有其他聊天，但引用 A 回复“详细” | 发送 A 的正文 |

直接回复依赖 NapCat 的 `get_friend_msg_history`，只查询目标私聊最近 20 条消息，以当前请求的消息 ID 定位，再用 `real_seq` 核对前一条消息及连续性。消息 ID、`message_seq` 和秒级时间戳均不用于排序。图片、表情、转发等其他消息也会打断相邻关系；不能跳过它们查找更早的通知。

单次历史查询最多等待 3 秒；当前消息尚未同步到历史、缺少前一条记录或查询暂时失败时，间隔 0.3 秒最多重试一次。历史查询不可用、序号缺失/重复/有间断或无法匹配通知时，不触发正文推送，仍可使用引用方式。历史记录仅在本次请求内用于匹配，不落盘、不传给 AI、不输出聊天正文到日志。

正文首次抓取失败时，推送会说明原因。再次引用索取正文会尝试抓取；已有成功快照则复用，保持摘要与原文一致，不自动刷新成网站修改后的内容。

正文图片使用相同学校会话下载，仅访问 `info.hitsz.edu.cn`，支持 PNG/JPEG/GIF/WebP，单张最多 5 MB、单篇最多 20 张且总计 20 MB。无法获取、超限或不支持的图片在包内逐项说明并保留可用链接。**本阶段不下载 PDF、Word、压缩包等独立附件，只提供名称和链接。**附件下载留待下一阶段。

QQ 明确拒绝合并转发时，当前包降级为普通分段消息和图片。超时或缺少有效回执表示结果未知，不立即重复发送整个包；后续可以检查聊天记录并重新请求。长通知可能分成多包，途中失败时可能已收到前面的内容。

## 登录和会话续期

账号密码由 AstrBot 保存于本地插件配置；密码框遮罩不会加密磁盘文件。Cookie 位于：

```text
data/plugin_data/astrbot_plugin_monitor_notifications/cookies.txt
```

每次请求先复用 Cookie。门户会话失效后会尝试 CAS 续期：若统一认证会话仍有效，识别 `caslogin.jsp` 中转页后重新访问原来的列表、详情或图片地址。需要密码登录时重新获取 `execution` 和动态盐，加密提交密码及 `rememberMe=true`。门户返回 401/403 时仅清理门户 Cookie，保留统一认证和可信设备 Cookie。

是否需要重新登录以学校返回为准，不依赖固定七天倒计时。学校要求滑块、App、短信或其他二次认证时，无法仅凭账号密码完成，会明确提示人工验证。人工验证必须与插件使用同一会话，并将验证后的 Cookie 保存给插件；其他浏览器单独登录不会自动同步。是否再次要求验证由学校策略决定。

列表抓取的登录、网络或解析失败会推送提醒，并按检查间隔重试。同一次持续故障每 24 小时最多提醒一次，重启仍保留提醒时间；成功抓取后重置限制。提醒发送失败则下一轮重试，错误同时记录日志。单条详情抓取失败会在该通知中说明，避免静默只发链接。

## 本地状态与升级

插件数据目录保存：

- `state.json`：已见 ID、待推送队列及故障提醒时间，兼容 v0.2。
- `articles/<通知ID>.json`：正文快照及成功生成的摘要。
- `articles/replies.json`：按目标会话隔离的 QQ 消息 ID 与通知 ID 映射。
- `images/`：正文内嵌图片缓存。

新建数据文件权限为 `0600`，目录为 `0700`。缓存持续保留以支持旧消息引用，目前不自动清理。源码不包含真实帐密、Cookie 或正文缓存。

升级会保留旧的账号、会话、检测间隔和去重状态；新增配置使用默认值。无需重新建立基线，也不会主动补推所有旧通知。成功取得 QQ 消息 ID 并保存映射后才确认送达；如果送出后回执丢失、或保存映射前进程退出，下轮重试仍可能重发。固定扫描前 3 页，长时间停机可能漏掉窗口外通知。

## 验证

```bash
python3 -m unittest discover -s tests -v
```

离线测试使用模拟学校、模型和 QQ，覆盖登录续期、摘要降级、正文/图片解析、引用映射、相邻消息匹配、历史同步重试、完整内容分段和发送失败处理。不会向真实 QQ 发消息。`test_event_handler.py` 在安装 AstrBot SDK 时验证真实事件处理器，SDK 不可用时跳过。开发时另用本机 AstrBot 4.28.1 SDK 验证加载和事件处理；v0.3.0 已用临时复制的 Cookie 只读验证一篇真实通知及内嵌图片。直接回复功能的真实 QQ 端到端验证仍需部署后进行。

解析依据为 HITA 的 `CampusNoticeParser` 和[本地参考说明](HITA_CAMPUS_NOTICE_IMPLEMENTATION.md)。登录依据为学校公开的 [login.js](https://ids.hit.edu.cn/authserver/cusHitnew/static/web/js/login.js) 与 [encrypt.js](https://ids.hit.edu.cn/authserver/cusHitnew/static/common/encrypt.js)。
